# text-patch

English · [简体中文](https://github.com/wintercn/text-patch/blob/main/README.zh-CN.md)

`text-patch` represents changes between two JavaScript strings as a serializable patch. It works with Markdown source or other text, but does not parse Markdown syntax. It has no runtime dependencies.

Patch generation can compare whole lines first, then refine suitable changed regions at the character level. Both layers use the Myers diff algorithm (Eugene W. Myers, [original paper PDF](https://neil.fraser.name/writing/diff/myers.pdf), [journal DOI](https://doi.org/10.1007/BF01840446)): it searches for an edit path made of insertions and deletions between two sequences. To limit work, the library falls back to replacing a region when its diff capacity is exceeded. The resulting patch is therefore not guaranteed to be globally minimal. All operation lengths use JavaScript string UTF-16 code units—the units counted by `string.length`.

## Install and use

```sh
npm install text-patch
```

The package exposes an ESM JavaScript entry point and TypeScript declarations.

```ts
import { applyPatch, createPatch } from 'text-patch';

const before = '# Heading\nOld text\n';
const after = '# Heading\nNew text\n';

const patch = createPatch(before, after);
const serialized = JSON.stringify(patch);
const restored = applyPatch(before, JSON.parse(serialized));

console.assert(restored === after);
```

Apply a patch to the same base string used to create it. `applyPatch` does not check that the base string matches and does not define behavior for malformed patches.

## Public API

```ts
createPatch(before: string, after: string, options?: PatchOptions): Patch
createCharacterPatch(before: string, after: string, diffCapacity?: number): Patch
createLinePatch(before: string, after: string, diffCapacity?: number): Patch
applyPatch(before: string, patch: Patch): string
```

- `createPatch` finds unchanged lines and refines suitable changed regions at the character level. This is the usual choice for multiline text.
- `createCharacterPatch` compares UTF-16 code units directly. Use it for a single line or when character-level capacity needs independent control.
- `createLinePatch` compares complete lines without character-level refinement.
- `applyPatch` executes a patch against its base string and returns the resulting string.

`PatchOptions` accepts independent `characterDiffCapacity` and `lineDiffCapacity` settings. The third argument of each standalone diff function controls only its own layer. A capacity must be a positive, finite number. A larger value permits more element comparisons before fallback; it is a performance capacity, not an exact edit distance or difference percentage. A fallback still reconstructs the target string, but may use a coarse delete-and-insert operation instead of a shortest edit path. See the [algorithm guide](https://github.com/wintercn/text-patch/blob/main/docs/algorithm.md) for defaults and details.

## Patch format

```ts
enum PatchOpcode {
  Retain = 0,
  Delete = 1,
  Insert = 2,
}

type Patch = {
  ops: PatchOpcode[];
  args: number[];
  insertText: string;
};
```

`ops[i]` pairs with `args[i]`. `Retain` and `Delete` arguments are lengths in the base string. An `Insert` argument is the next length to consume from `insertText`, which stores all inserted text in operation order. A patch can be serialized directly as JSON and has no format-version field.

An edit boundary may fall inside a surrogate pair or a multi-code-point emoji. The algorithm does not use Unicode code points or grapheme clusters as edit units. Applying a patch generated by this package to its original base string still reconstructs the exact target string. A UI can adjust visual highlight boundaries separately.

## Develop and test

```sh
npm install
npm run build
npm test
```

The build writes to `dist/`. The npm package includes compiled output, source, and user documentation, but excludes test materials. See the [test guide](https://github.com/wintercn/text-patch/blob/main/tests/README.md) for test coverage and upstream provenance.
